# 🦷 틀니케어 (DentureCare)

> 틀니 사용자를 위한 일일 관리 루틴 · 치과 검진일 기록 · 가족 연동 앱

**웹 앱:** [틀니케어](https://myun-hazel.vercel.app)

아이폰 검수는 [Xcode 설치 안내](README_설치방법.md), 출시 준비는 [점검표](RELEASE_CHECKLIST.md)를 참고하세요. 이 검수 브랜치의 변경은 운영 웹 배포와 별개입니다.

현직 치과위생사(7년차)가 임상에서 마주한 문제 —
"틀니 관리법을 알려드려도 집에 가면 잊어버리시고, 검진 시기를 놓쳐 잇몸이 상한 뒤에야 오신다" —
를 해결하기 위해 직접 기획하고 개발한 앱입니다.

## 무엇이 다른가

### 1. 담당 치과가 정한 검진일 기록

검진일을 입력·변경·삭제하고 연결된 보호자와 공유합니다. 제작 연·월은 사용 기간을 표시하는 데만 사용하며 검진 간격을 추정하지 않습니다. 이전 버전이 계산한 날짜는 참고값으로 구분합니다. 실제 예약 접수와 검진일 알림은 제공하지 않습니다.

### 2. 일상 관리 기록과 출처 있는 안내

기상·식후·취침 시점의 관리 기록과 시간 설정을 제공합니다. 부드러운 솔, 비연마성 세정제, 식후 헹굼, 취침 시 제거 등 NHS·ADA 자료를 참고한 안내에 출처를 표시합니다. 재질과 상태에 따라 담당 치과와 제품 설명서를 따릅니다. 앱의 하루 5개 체크 항목은 임상 효과가 검증된 처방이 아닙니다.

### 3. 가족 연동 — 이 앱의 핵심

고령 사용자 혼자서는 관리 지속이 어렵습니다. 6자리 초대코드로 자녀·배우자를 연결하면:

- 앱을 열면 부모님의 오늘 관리 현황을 확인하고 주기적으로 갱신
- 도움 요청(잇몸 통증, 틀니 파손 등)을 **보호자 앱에서 확인**. 앱이 닫힌 상태의 푸시 전달은 미구현
- 보호자는 **읽기 전용** — 데이터베이스 차원에서 강제 (RLS)

### 4. 고령자 접근성 우선 설계

본문 18px 이상(설정에서 22px로 확대 가능) · 터치 영역 48px 이상 · 한 화면 한 과업 ·
전문 용어 배제("리콜" → "치과 가는 날")

### 5. 건강정보 검수

검증하지 못한 보험 급여 수치와 일률적인 교체 주기는 안내에서 제외했습니다. [건강정보 검수 기록](CLINICAL_CONTENT_REVIEW.md)에 출처와 남은 검수 항목을 정리했습니다.

## 프로젝트 구조

```
├── src/
│   ├── screens/      화면 컴포넌트 (인증·온보딩·홈·진행률·검진·설정)

│   ├── state/        전역 인증 상태
│   └── components/   공통 UI (고령자 접근성 기준 적용)
├── db/migrations/    데이터베이스 스키마 + 보안 정책 (SQL)
├── docs/설계/        설계 문서 (화면·시나리오·데이터 모델·API 명세)
└── ios/              iOS 네이티브 프로젝트 (Capacitor)
```

## 로컬에서 실행하기

```bash
npm ci
```

`.env.example`을 복사해 `.env`를 만들고 Supabase 접속 정보를 입력합니다.

```bash
npm run dev
```

데이터베이스는 `db/migrations/`의 적용 순서를 [설치 안내](README_설치방법.md)에서 확인하세요. 기존 DB에 `001`을 다시 실행하지 않습니다. 계정 관리에는 `004_account_safety.sql`, 검진일 기록에는 `005_checkup_schedule.sql`이 필요합니다.

검증: `npm run verify` · Mac에서 Xcode 열기: `npm run ios:run`. 현재 소스는 `src/`이며 `app/`은 이전 프로토타입입니다.
